1. 소프트웨어 설계의 개요
   - 정의: 요구사항 분석에서 정의된 결과로 얻은 요구사항 명세를 기초로 소프트웨어의 기능 및 성능 등을 가장 적합하게 실현시킬 수 있는 알고리즘과 그 알고리즘에 의해서 처리될 자료 구조의 특성을 찾아내어 이들을 문서화하는 과정이다.
2. 소프트웨어 설계 목표
   1. 시스템의 구성과 이에 필요한 데이터 추상화
   2. 시스템의 각 구성요소 사이에 있는 인터페이스 확립
   3. 제어와 데이터의 연결을 명확히 정의
   4. 목표한 시스템의 품질 보증을 위한 설계상 장단점 파악 → 개선 방향 제시
3. 소프트웨어 설계원리
   1. 추상화
      - 자세한 구현에 대한 고민에 앞서서 상위수준에서 제품의 구현을 먼저 생각하는 것이다.
      - 큰 흐름을 잃지 않으면서 점차적 구현으로 접근하기 위한 목적이다
      - 종류: 제어 추상화, 기능 추상화, 자료 추상화
   2. 단계적 분해
      - 문제를 상위수준에서 점증적으로 좀 더 구체적인 하위수준으로 분할하는 기법이다.
      - 소프트웨어를 해결할 만한 작은 문제로 나누고 구체화의 정도를 작게 하여 점증적으로 문제를 다루어 나가는 방법
   3. 프로그램 구조 (분할과정)
      - 시스템의 특성을 파악하여 기존 시스템들의 경험과 가이드라인을 활용할 수 있다.
   4. 모듈화
      - 모듈은 독립적으로 수행할 수 있는 프로그램 단위를 의미하며 함수, 서브루틴, 작업단위 등으로 불리기도 한다.
      - 모듈화는 소프트웨어를 모듈 단위로 나누는 것을 의미한다.
